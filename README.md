# タブまとめ（Google Tasks 優先度レポート用の Chrome 拡張）

> タスク優先度レポート（Google Tasks を採点して並べる Apps Script の Web アプリ）と組み合わせて使う拡張機能です。単体では動きません。
> フォルダを開く機能は、別のツール [open-path](https://github.com/RBelg/open-path) が担当しています。

優先度レポートの各行に出る「**まとめ**」ボタンから、そのタスクに紐づくページを
まとめて開き、**タスク名のタブグループ**にします。

タブグループを作る API（`chrome.tabGroups`）は**拡張機能からしか呼べない**ため、
レポート画面だけでは実現できません。この拡張がその役を担います。

## 入れ方（1回だけ）

1. Chrome で `chrome://extensions` を開く
2. 右上の「**デベロッパー モード**」をオンにする
3. 「**パッケージ化されていない拡張機能を読み込む**」→ このフォルダを選ぶ
4. レポートのページを開き直す

> Chrome を起動するたびに「デベロッパー モードの拡張機能を無効にする」という
> 確認が出ます。閉じれば動き続けます（消す方法は Chrome ウェブストアへの登録のみ）。

## 何をしているか

| ファイル | 役目 |
| --- | --- |
| `inject.js` | レポート画面の枠内に入り、`<html>` に印を付け、ページからの依頼を中継する。**何度読み込まれても二重にならない**作り |
| `background.js` | タブを開き、`chrome.tabs.group()` でまとめ、`chrome.tabGroups.update()` で名前と色を付ける。あわせて、**ページが落ち着いた頃に `inject.js` を差し込み直す** |

- グループ名は**4文字**に切り詰めます（`[P1]` や `Re:` は落としてから切る）
- 色は優先度に対応（P1=赤 / P2=橙 / P3=青 / P4=灰）
- **同じ名前のグループが既にあれば、そこに足します**（押すたびに増えない）
- **タスクを完了したとき・「明日へ」・「対応中」を外したときに、そのグループを閉じます**。
  タブグループを消す命令は無いので、中のタブを閉じます。
  **先に `chrome.tabs.ungroup()` でグループから外してから閉じます**。いきなり閉じると
  Chrome が「グループを閉じた」とみなし、保存済みのタブグループとして残ってしまうため。
  レポート側が取り消しの猶予（完了は10秒、対応中を外したときは3秒）を待ってから頼むので、
  その間に戻した場合は閉じません。
- **放置されたグループを片付けます**（1.6.0〜）。この拡張が作ったグループの名前を覚えておき
  （`storage` 権限はこのため）、レポートを開いたとき・描き直したとき・5分おきに
  「対応中・あとで対応のタスク」以外のグループを閉じます。完了した・消えた・先送りした・
  名前を変えた・Chrome の再起動で残った、などで取り残されたものが対象です。
  自分で作ったグループ（覚えていない名前で、どのタスクとも一致しないもの）には触りません。
  レポートで触ったばかりのタスク（取り消しの猶予中）は残します。
- **Google Tasks のアプリやスマホで完了にした分も、後から閉じます**（1.5.0〜）。
  レポートを開いたときと1分ごとの更新のたびに、完了済みタスクのグループ名を
  まとめて送ってきます（`close-groups`）。未完のタスクと同じ名前のものは送られません。
  **名前の照合は `tabGroups.query({title})` に任せず、全グループを取って自分で比べます**
  （query の title はパターン扱いで、記号を含む名前だと当たらないため）。
  窓も絞りません（押した窓とタブを開いた窓が違うことがあるため）。
  見つからなかったときは、**いま存在するグループ名を返して**レポート側に出させます
- タブは**いったん全部を裏で開いてから、最初の1枚を前面に出します**
  （1枚ずつ前に出すと開いている間ちらつくため）。窓も前面に出します

## 差し込み先（ここを間違えると動かない）

レポートの中身は `script.googleusercontent.com` ではなく、
**`n-xxxxxxxx-0lu-script.googleusercontent.com` のような毎回変わるサブドメイン**で動きます
（親ページの `iframe#sandboxFrame` の src を見ると分かります）。
ホストを決め打ちすると差し込まれないので、**パス `/userCodeAppPanel` で絞って**います。

```json
"matches": ["https://*.googleusercontent.com/userCodeAppPanel*"]
```

差し込まれているかは、レポートの iframe のコンソールに
`[タブまとめ] 用意できました` が出るかで確かめられます
（DevTools のコンソール上部で、フレームを `userCodeAppPanel` に切り替えてください）。

## 差し込み直しが要る理由（ここが最大の落とし穴）

レポートの中身は、**親ページが後から `document.write` でこの枠に流し込みます**。
この書き込みで**文書が作り直される**ため、最初に差し込んだぶんは
付けた印もタイマーも**道連れに消えます**。

症状はこうなります。

- 枠のコンソールには `[タブまとめ] 読み込みました` が出る（差し込み自体は成功している）
- なのにページからは拡張が見えず、「拡張機能が見つからない」と言われる

対策として `background.js` が **0/1.2/3/6/10秒の5回、`inject.js` を差し込み直します**
（`chrome.scripting.executeScript`）。書き込みの後に入ったぶんが、生きている文書に印を付けます。

ページ側は**ボタンを押した瞬間に印を読む**ので、名乗りの前後関係に左右されません。

## 拡張機能を読み込み直したとき

**読み込み直すと、先に入っていたぶんは「孤児」になり `chrome.runtime` を失います。**
古い受け口が残ったままだと、押したときにそこが掴んでしまい

```
Uncaught TypeError: Cannot read properties of undefined (reading 'sendMessage')
```

で止まります。対策は3つ入れてあります。

- **受け口は差し込むたびに作り直す**（古いものを外してから登録する）
- **`chrome.runtime.id` を毎回確かめる。** 切れていれば `<html>` の印を外し、
  「ページを開き直してください」とレポートに返す（黙って止まらない）
- **起動時に、開きっぱなしのレポートへ入れ直す**（`chrome.tabs.query` → `executeScript`）

3つ目があるので、ふつうは**ページを開き直さなくても**次の操作から繋がります。

## 安全のための作り

- 受け取るのは**自分のフレームから来たメッセージだけ**（`event.source !== window` は捨てる）
- 開くのは **http(s) と `chrome:`（設定画面など）のみ**。`javascript:` や `file:` は弾く。
  `chrome:` を通すのは、**ページからは開けず拡張の `tabs.create` でしか開けない**ため
- 1回に開くのは**最大12件**

権限は `tabs` / `tabGroups` / `scripting` の3つ。`scripting` は上に書いた
「差し込み直し」に要ります。対象は `script.google.com` と `googleusercontent.com` で、
差し込んだ先でも `/userCodeAppPanel` 以外なら即座に何もせず抜けます。ページの中身は読みません。

## 入れていない場合

レポート側は拡張の有無を見ていて、入っていなければ**まとめずに普通に開きます**
（「まとめるには拡張機能が要ります」と表示）。
ただしブラウザのポップアップブロックで2枚目以降が止まることがあります。
